что сильнее всего нагружает игру. Всё измерено, а не угадано: замер — `--mshots-from=perf` (tools/mission_shots.gd),
1920×1080, без вертикальной синхронизации; файл `perf.txt` в папке снимков. Поведение проверено полным набором тестов
(222 теста; бот проходит главы с теми же цифрами, что и до оптимизации: Берег 38/40, Академия 16/20, те же дни).

## 2. Что было не так и что сделано

1. **Метки событий пересчитывались каждый кадр** (`mission_game._update_pins` в `_process`): для каждого ромба —
   путь фигуры по графу, срок, вода. Теперь — при изменении состояния (сигналы) и проверкой «слепка» раз в 0,5 с.
2. **Карта-план пересобиралась дважды в секунду** (`_update_tide` → `SleeperMap.sync`: облик всех мест, угрозы,
   местность, следы, туман) — теперь только когда сдвинулось состояние.
3. **Два сигнала — два обновления экрана**: `missions_changed` и `state_changed` приходят парой → одно отложенное
   обновление в конце кадра (`_queue_refresh`).
4. **`MapRules.config` перебирал все ~130 мест** при каждом вызове (сотни раз за обновление через `anchor`,
   `size_of`, `links`, `known`) — ответ по главе запоминается в `content.memo` (контент после загрузки не меняется).
5. **Путь к каждому событию искался отдельно** (`FigureRules.reach` → поиск пути и соседи фигуры на событие) — новый
   `FigureRules.reach_all` и `TravelRules.distances`: один обход графа на всех (те же правила, та же длина пути;
   это подтверждают тесты — бот играет с теми же цифрами). Используют планировщик, метки, подсказки, задания, бот.
6. **Туман войны** — шейдер на каждом пикселе экрана перебирал до 48 кругов и 64 коридоров каждый кадр. Теперь маска
   «где открыто» считается в своей текстуре (половина разрешения основы, `sleeper_fog_mask.gdshader`) и только когда
   открытое меняется (проявление места, новые места); туман берёт из неё одно значение. Вид тот же — сравнение
   с эталонными снимками: средняя разница 1–2 из 255 (это движение облаков и частиц).
7. **Подписи мест рисовались каждый кадр** (с обводками) — свой слой `_labels`, перерисовка при смене карты
   (живое «дыхание» — только у серебряного стиля).
8. **Ромбы событий перерисовывались каждый кадр** — теперь только пока движутся (наведение, круг загрузки, рост,
   отряд, вспышка задания) или пульсирует сюжетный.

## 3. Старый код — удалено

Нигде не вызывались (проверка поиском по всему проекту и сценам):
`GameState.has_run`, `GameState.mission_tick` (пустая «часы реального времени» — вызывалась каждый кадр),
`ProfileService.known_count`, `EdgeRules.shown_death`, `ModifierRules.defs`, `PsycheRules.decay` (распад психики по
секундам — из времён часов), `StatResolver.requirements`, `TideRules._stuck`, `MapBackdrop.tod_for_week`,
`MapBackdrop.tod_name` и `TOD_NAMES`, `SleeperMap._ellipse_ring/_ellipse_fill` (старые кольца вместо подсветки),
`MissionWindow._squad_for`, `Palette.chance_color` (шкала шанса), `UITheme.stat_icon`.

**Оставлено намеренно** (используется или нужно для отката): старое передвижение шагами (`movement = steps`:
`TravelRules`, `_add_move_buttons`, окно перехода) — для отката на ветку без фигуры и тестов; карты-метки событий
вместо ромбов (настройка); `TideLayer` (вода для глав без карты-плана); поле `rest_until` в сохранении — формат
сохранений не меняли.

## 4. Что сейчас нагружает игру больше всего

1. **Отрисовка карты-плана и ряда героев — основа кадра (~2,5–3 мс, 250–280 вызовов отрисовки).** Слои основы,
   виньетки мест, тропы, следы и метки, вода по высотам; ряд героев — карты с живыми аурами (перерисовываются каждый
   кадр) и покачиванием. Разбор по частям (кадр без части): каждая стоит 0,1–0,4 мс, ни одна не главная.
2. **Всплеск после каждого действия — 7–10 мс на Береге** (меньше кадра при 60 FPS, заметно не дёргает):
   пересборка карты-плана `SleeperMap.sync` 2,5–3 мс (облик мест, угрозы, местность, следы, туман), события
   обучения 2 мс, задания и строка дня ~1 мс, метки 0,6 мс.
3. **Мысли героев** — подбор реплики 1,5 мс раз в минуту — незаметно.
4. **Память** — ~94 МБ (текстуры карт и карт героев).
5. **Не измерено**: экран боя (лучи, граф связей) и планшет карты — следующий кандидат на замер.

## 5. Что можно сделать дальше (не делалось — риск поменять поведение)

- Запоминать `MapRules.links` до следующего изменения состояния: `sync` ускорится ещё в 2–3 раза (нужен счётчик
  изменений состояния).
- Ауры карт в ряду героев — перерисовка 30 раз в секунду вместо каждого кадра.
- Замер экрана боя.
- Тесты: прогоны бота (фигура, переходы, баланс) — ~25–35 мин; можно выделить «быстрый» набор.
