# 1. Концепция

## 1.1. Паспорт игры

| Параметр | Значение |
|---|---|
| Название | **SunLess** `[Решение владельца]` (Санлес — истинное имя Санни; проверить на совпадения с чужими товарными знаками перед публичным релизом, см. 11) |
| Жанр | сюжетная карточная игра-приключение (narrative card adventure) |
| Режим | одиночный, пошаговый |
| Движок | Godot 4 (GDScript), 2D |
| Платформа | Windows (первая), затем Linux / macOS; Web — как опция для демо |
| Управление | мышь (основное), клавиатура (полная навигация), геймпад — позже |
| Язык | русский (основной), архитектура сразу под локализацию |
| Длительность | вертикальный срез E01–E11: 30–45 мин; том 1 (E01–E48): 4–6 ч; оба тома (E01–E112): 10–14 ч |
| Первоисточник | «Теневой раб» (Guiltythree): тома «Дитя Теней» и «Мрачный город» |
| Референс по ощущению | Sultan's Game (карточный интерфейс, риск, последствия), Slay the Princess / Citizen Sleeper (вес выбора), Inscryption (тактильность карт) |

## 1.2. Логлайн

> Ты — Санни, раб в Кошмаре, который не может победить силой. Каждую сцену истории ты решаешь, собирая **одного героя, до трёх карт-возможностей и один из трёх способов действия** — и живёшь с последствиями: травмами, находками и тем, кем ты становишься.

## 1.3. Столпы дизайна

Каждое решение в разработке проверяется этими четырьмя вопросами. Если фича не усиливает ни один столп — она не нужна.

| # | Столп | Что значит на практике |
|---|---|---|
| 1 | **Решение собирается, а не выбирается** | Игрок не жмёт «вариант 2». Он собирает комбинацию «персонаж + усиления» и видит, как три шанса меняются в реальном времени. Интересный момент — перекладывание карт, а не бросок. |
| 2 | **Честный риск** | Требования и шанс всегда видны. Бросок прозрачен (шкала + стрелка). Игрок всегда понимает, почему проиграл. Никаких скрытых штрафов к шансу. |
| 3 | **Последствия остаются на карточках** | Травма — это карта, прилипшая к персонажу. Находка — новая карта в руке. История «записывается» в коллекцию, а не в полоску HP. |
| 4 | **Мир книги уважается** | Термины не смешиваются (Шлюз ≠ Врата, ранг ≠ редкость). Где игра отходит от канона — это помечено. Игрок всегда знает, что было в книге, а что — игровая адаптация. |

## 1.4. Чем игра НЕ является

- Не колодострой: нет колоды, добора, сброса, случайной руки. `[Зафиксировано]`
- Не RPG с прокачкой уровней: рост характеристик редкий и сюжетный.
- Не тактический бой: сражение — это один из трёх способов пройти сцену, а не отдельный режим.
- Не визуальная новелла с ветвлением: основной сюжет туннельный, варианты меняют *как* и *какой ценой*, а не *куда*. `[Зафиксировано]`

# 2. Решения по открытым вопросам

Концепция (раздел 12) и файл [[09 — Открытые вопросы]] перечисляют вопросы, без которых нельзя программировать. Ниже — принятые в GDD ответы. Они подобраны так, чтобы вертикальный срез был проходимым и не заходил в тупик.

| # | Вопрос | Решение | Метка |
|---|---|---|---|
| D1 | HP / «Здоровье» | **HP нет.** Все строки «-1 Здоровье» / «восстановить здоровье» заменяются на выдачу/снятие конкретной травмы. U18 «здоровье ≤ 3» → «если на персонаже есть тяжёлая или критическая травма». | [Решение GDD] |
| D2 | Смерть персонажей | Погибнуть может **любой** персонаж, включая Санни. Смерть Санни = **конец прохождения** (экран «Тень угасла» → загрузка последнего сохранения или контрольной точки начала арки). Смерть другого героя: его усиления возвращаются в панель, варианты, требующие его, блокируются. | [Решение владельца] |
| D3 | Критерий смерти | Когда у персонажа **больше двух травм**, появляется шанс смерти: при 3 травмах — **15%**, каждая следующая травма **+20%** (4 → 35%, 5 → 55%, 6 → 75%, 7 → 95%, 8+ → 100%). Бросок смерти делается **в момент получения новой травмы**, если после неё травм ≥ 3. Подробно — 4.5. | [Решение владельца] |
| D4 | Какой вариант продвигает сюжет | **Только сюжетный вариант** (один из трёх, значок «книга»). Успех двух других даёт их награду, но событие **остаётся на поле**, а выполненный несюжетный вариант становится недоступным (нельзя «фармить» награду). Так несюжетные варианты работают как **подготовка** к сюжетному: получить оружие, знание, бонус — и потом идти на главную проверку. Исключение — наградные события (`reward`, E11, E17): игрок выбирает один вариант, и событие закрывается с продвижением. | [Зафиксировано] + [Решение владельца] |
| D5 | Способности персонажей | Способности (Контроль Теней, Теневое усиление, Бессмертное Пламя, Пророческое Видение, Вспышка Скорости…) — **отдельная сущность, не усиления**. Они принадлежат персонажу, показываются на его карте, **не занимают слоты** усилений, не лежат в нижней панели, не передаются и не изнашиваются. Три слота остаются только для усилений. | [Решение владельца] |
| D6 | Появление событий | Сюжетные события появляются **без инициаторов**, после успеха предыдущего — **со случайной задержкой** (D21). Кроме того, на карте **сами** появляются случайные события из пула региона (4.6). Инициаторы случайных событий **не создают** — только конкретные. Исключение — обучающий `Первый сон`, который запускает E01. | [Решение владельца] |
| D7 | Инициаторы | **Одноразовые**: после применения карта исчезает и в панель не возвращается. Применяются **в любом месте** карты мира. Всегда создают **одно конкретное** событие, указанное в данных. | [Решение владельца] |
| D8 | Выбор травмы при провале | Травма выбирается **случайно** из травм, которых у персонажа ещё нет. Вариант может сузить пул (например, только физические для боя) — поле `trauma_pool`. T07 «Очарованный» и T09 «Боль» в случайный пул не входят: они выдаются только сценарием. | [Решение владельца] + [Решение GDD] для пула |
| D9 | Поломка усиления | У каждого усиления есть **износ**: шанс поломки при первом использовании **1%**, после каждого использования **+5%** (1 → 6 → 11 → 16…). Бросок поломки — после каждого разрешённого события, где карта была приложена, при любом исходе. **Сломано = карта уничтожена** и исчезает из коллекции. Подробно — 4.4. | [Решение владельца] |
| D17 | Ремонт | Событие **«Легендарный кузнец»**: за монеты **только сбрасывает износ** усиления до 1%. Уничтоженную карту восстановить нельзя. Появляется как случайное событие в поселениях и по инициатору «Знак кузнеца». Цены — 4.12. | [Решение владельца] |
| D18 | Что не ломается | Способности персонажей (D5), карты-знания и Эхо **не изнашиваются**: это не предметы. Ломаются Воспоминания, оружие, броня, подготовка, импровизированные вещи. | [Решение владельца] |
| D10 | Видимость последствий | **Требования видны всегда.** Последствия видны как **иконки типов** (карта / травма / знание / сюжет). Конкретное содержимое скрыто знаком `?`, пока не раскрыто способностью (Контроль Теней, Видение Касси), картой-знанием или прошлой попыткой. Это даёт смысл способностям-разведчикам и не нарушает правило о видимых требованиях. | [Решение GDD] |
| D11 | Неделя | Условный **ход**, не календарь книги. Используется для счётчика, журнала и временных эффектов «на N ходов». Давления сроков нет. | [Решение GDD] |
| D12 | Мана и монеты | Старт: **10 маны и 10 монет**. Оба ресурса добываются в событиях с **примерно равным шансом**, но тратятся по-разному: **монеты** — на мир людей (ремонт, лечение тела, торговля, подкуп), **мана** — на силу Заклинания (прозрение, концентрация, оберег от смерти, ментальное лечение, ритуалы). Цены и доход — 4.12. Осколки души — отдельный ресурс Мрачного города (Фаза 5). | [Решение владельца] + [Решение GDD] для цен |
| D13 | Начальный набор | Санни (стадия «Раб») + инициатор `Первый сон`. Больше ничего. | [Решение GDD] |
| D14 | Объём первого релиза | Вертикальный срез E01–E11 → решение о томе 1 (E01–E48) как первом полном релизе. | [Решение GDD] |
| D15 | Сюжетный вариант с двумя героями (E112) | Исполнитель — Санни; Нефис — условие (`required_in_collection`) и участница финального противостояния. Второго слота не вводим. Книжный итог — Нефис заставляет Санни пройти Врата. | [Решение GDD] |
| D16 | Избыток по нетребуемым характеристикам | В компенсации участвуют **только характеристики с требованием > 0**. Иначе проверка одной Хитрости почти всегда даёт 100% за счёт Силы и Воли. | [Решение GDD] |
| D19 | Сколько травм при провале | По умолчанию провал = **1 случайная травма**. Варианты с тегом `high_danger` дают **2**. Вариант может задать 0 (провал без травмы). | [Решение GDD] |
| D21 | Задержка сюжета | После успеха сюжетного события следующее появляется через **0, 1 или 2 недели** (равновероятно). Пока оно в пути, в верхней панели горит знак «Надвигается…». **Защита от тупика:** если на карте не осталось ни одного события, ожидающее сюжетное событие появляется немедленно. Переход между арками — без задержки. | [Решение владельца] + [Решение GDD] для чисел |
| D20 | Случайные события | Каждую неделю после хода — бросок **30%**: на карте появляется случайное событие из пула текущего региона (без повторов, пока пул не исчерпан). Лимита событий на поле нет `[Зафиксировано]`. | [Решение GDD] |

# 3. Игровой цикл

## 3.1. Три уровня цикла

```text
КАМПАНИЯ   Арка (Первый Кошмар) → Арка (Академия) → ... → Финал тома
              │
АРКА        Регион на карте → сюжетные события по цепочке + побочные события
              │
ХОД         Открыть событие → назначить персонажа → 0–3 усиления →
            нажать вариант → бросок → результат → +1 неделя → автосохранение
```

## 3.2. Ход по шагам (с точки зрения игрока)

| Шаг | Игрок делает | Игра показывает | Время идёт? |
|---|---|---|---|
| 1 | Кликает карту-событие на карте мира | Открывается планшет: арт, текст, 3 варианта | нет |
| 2 | Перетаскивает персонажа в «кармашек» | Итоговые Сила / Воля / Хитрость, все 3 шанса пересчитаны | нет |
| 3 | Перетаскивает 0–3 усиления на персонажа | Веер карт, изменения цифр (зелёные/красные), шансы обновлены | нет |
| 4 | (Опционально) переключается на другое событие | Черновик сохраняется на этом событии, карты помечены «Черновик» | нет |
| 5 | Нажимает кнопку варианта | Анимация броска на шкале шанса | — |
| 6 | Смотрит экран результата | Что проверялось, шанс, выпавшее число, полученные/потерянные карты | — |
| 7 | Нажимает «Дальше» | Счётчик недели +1, новые события появляются на карте, автосохранение | **да** |

`[Решение GDD]` Назначение персонажа — **черновик хода**, а не начало хода. Ход совершается только нажатием варианта. Так случайное перетаскивание ничего не ломает. Персонаж из черновика одного события показывается в панели с меткой «Черновик: E03» и может быть переназначен (он автоматически снимается со старого черновика).

## 3.3. Минута игры (пример)

> На карте горной дороги светится карта-Таро «III — Личинки Горного Короля». Игрок открывает её. У Санни-раба Сила 3 — «Драться цепью» (Сила 5 / Воля 5) показывает 80%. «Использовать окружение» (Хитрость 7) — 85%, и в награде виден значок карты с `?`. «Уклониться и переждать» — 100%, но награды нет. Значок книги стоит у «Использовать окружение» — только этот вариант продвинет историю. Игрок рискует: нажимает его. Стрелка бежит по шкале и останавливается на 91 — за пределами 85. Провал. Из пула физических травм выпадает «Рваная рана» — карта с треском прилипает к Санни: Сила 3 → 2. Ещё две травмы — и на карте Санни появится череп. Событие осталось на поле. Неделя 3. Теперь безопасное «Уклониться и переждать» (100%) выглядит разумной подготовкой: оно не продвинет сюжет, но даст +1 Хитрость к следующей попытке и раскроет, что именно даст сюжетный вариант.

# 4. Механики

## 4.1. Коллекция и нижняя панель `[Зафиксировано]`

- Все полученные карты лежат в нижней панели. Колоды, добора, сброса нет.
- Дубликатов персонажей и усилений нет. Попытка выдать уже имеющуюся уникальную карту → ничего не происходит (в журнал: «уже есть»).
- Вкладки-фильтры: **Все · Персонажи · Усиления · Инициаторы**. Травмы в панели отдельно не лежат — они видны на карте персонажа.
- Состояния карты в панели:

| Состояние | Вид | Можно использовать |
|---|---|---|
| Свободна | обычный | да |
| Черновик | маленькая метка с номером события | да (перенос снимает со старого черновика) |
| В планшете | приподнята, подсвечена рамкой | уже используется |
| Износ (усиление) | в углу — значок трещины и текущий шанс поломки, например `⚒ 11%`; от 30% — трещина на рамке | да |
| Уничтожена (усиление) | анимация раскола, карта исчезает из панели; запись в журнал | — |
| Не подходит владельцу | при перетаскивании — перечёркнутый контур | нет |
| Под угрозой (персонаж) | при 2+ травмах — значок черепа и шанс смерти при следующей травме, например `☠ 15%` | да |
| Погиб (персонаж) | чёрно-белая, лента траура; убирается в «Память» через 1 ход | нет |
| Ушёл (временный спутник) | анимация ухода, запись в Кодекс | нет |

## 4.2. Типы карт

| Тип | Функция | Рамка (визуально) |
|---|---|---|
| **Персонаж** | единственный исполнитель события | лунное серебро |
| **Способность** | сила персонажа; не карта в панели, а строка на карте персонажа (D5) | серебряная звезда `✦` |
| **Усиление** | предмет, навык, знание, подготовка, Эхо | тёмная бронза |
| **Травма** | состояние на персонаже | рваный багрово-чёрный край |
| **Инициатор** | создаёт побочное событие | фиолетовая тушь |
| **Событие** | сцена на карте мира: 3 варианта | Таро: римская цифра + арт |

## 4.3. Персонажи

### Поля карты

`id`, имя и альтернативные имена, **статус** (`playable` / `temporary` / `boss` / `lore`), роль, **ранг по книге** (Спящий, Пробуждённый, Мастер… — отдельно от чисел), редкость (визуально), Сила / Воля / Хитрость, черты (пассивные эффекты с тегами), недостаток, `run_ending_death` (true только у Санни), `stage`, `available_arcs`, `leaves_after`, источник по главам.

### Стадии персонажа `[Решение владельца]`

Архивные числа Санни (5 / 8 / 10) делают все проверки Первого Кошмара стопроцентными. Поэтому карта Санни **эволюционирует по стадиям** — это одновременно лор (раб → Спящий) и прогрессия:

| Стадия | Когда | Сила | Воля | Хитрость | Способности |
|---|---|---:|---:|---:|---|
| Санни — Раб | E01–E11 | 3 | 5 | 6 | нет Аспекта |
| Санни — Спящий | после E11 | 4 | 7 | 8 | Аспект, Недостаток, способность «Контроль Теней» |
| Санни — Санлес | начало «Мрачного города» | 5 | 8 | 10 | + Теневая Святая и пр. |

Числа предварительные; баланс — Фаза 1. Переход стадии — отдельная анимация (карта переворачивается, новая рамка). Постоянные бонусы, полученные раньше (E15, E17), **сохраняются** поверх базы новой стадии.

### Роли персонажей по статусу

| Статус | Кто (примеры) | Правило |
|---|---|---|
| `playable` | Санни, Нефис, Касси, Кай, Эффи | постоянные, исполнители |
| `temporary` | Шолар, Шифти, Ауро, Кастер | доступны в пределах арки, уходят по `leaves_after` |
| `boss` | Гунлауг, Харус, Горный Король | только как противник в тексте события |
| `lore` | P11–P13, Первый Владыка, наставники Академии (Джет, Рок, Юлий) | только в Кодексе и тексте событий |

Теневая Святая — отдельный тип **«Эхо/Тень»**: работает как усиление-спутник, принадлежащий Санни (`allowed_owner_ids: [P01]`), а не как человек-исполнитель. Окончательно — в Фазе 5.

### Занятость `[Зафиксировано]`

Один персонаж — одно событие. Поскольку за ход разрешается одно событие, занятость на практике значит «стоит в черновике».

### Способности `[Решение владельца]`

Способность — часть персонажа, а не карта в панели.

| Правило | Значение |
|---|---|
| Где видна | блок «Способности» на карте персонажа и в кармашке планшета |
| Слоты | не занимает; у персонажа могут быть способности + до 3 усилений |
| Как получить | сюжетом: команда `add_ability` (например, E11 → Контроль Теней у Санни) |
| Передача | нельзя: способность всегда у владельца |
| Износ | нет (D18) |
| Режимы | способность с выбором («+3 Сила ИЛИ +2 Хитрость») — переключатель в планшете; по умолчанию режим с лучшим шансом |
| «Раз за событие» | включается/выключается переключателем в планшете; цена (например, Боль у Бессмертного Пламени) показывается рядом |

Способности из архива `[04 — Усиления и травмы]` переносятся из списка усилений: U03 Контроль Теней, U04 Теневое усиление (Санни), U08 Бессмертное Пламя (Нефис), U09 Пророческое Видение (Касси), U13 Вспышка Скорости (Кастер). Их ID меняются на `A01–A05`, чтобы данные не путали способности и усиления. Постоянные атрибуты Санни — U05 Благословение Теней и U17 Плетение Крови — тоже переведены в способности (`A06`, `A07`): это черты персонажа, а не предметы, и они не должны изнашиваться.

**Баланс (Фаза 1):** способность без слота — чистая прибавка. Контроль Теней (+3 Хитрость всегда) превращает Санни-Спящего из 4/7/8 в 4/7/11. Если это обесценивает проверки Академии, безусловные бонусы способностей переводятся в условные (по тегам событий) или «раз за событие».

## 4.4. Усиления

| Правило | Значение | Метка |
|---|---|---|
| Максимум на персонаже | 3 | [Зафиксировано] |
| Дубликаты | запрещены | [Зафиксировано] |
| Использование | многоразовое до поломки; у каждого использования есть шанс поломки (износ) | [Зафиксировано] + [Решение владельца] D9 |
| Отрицательные модификаторы | разрешены (`+4 Хитрость / -1 Сила`) | [Зафиксировано] |
| Способности персонажа | не усиления: отдельный блок на карте персонажа, слотов не занимают | [Решение владельца] D5 |
| Условный бонус | действует, если у события есть нужный тег; иначе карта показывает бонус приглушённым с пометкой «не в этой сцене» | [Решение GDD] |
| Выбор режима (U04: «+3 Сила ИЛИ +2 Хитрость») | переключатель на карте в планшете; по умолчанию выбирается режим, дающий лучший максимальный шанс | [Решение GDD] |
| Разовые эффекты «раз за событие» | применяются автоматически при расчёте, если полезны; игрок может отключить | [Решение GDD] |

**Происхождение усиления** (поле `origin`): `memory` (Воспоминание), `aspect_ability`, `echo`, `skill` (навык), `knowledge` (знание), `preparation` (подготовка), `improvised`. Это нужно для лора и для будущих правил (например, «Эхо не может получить ментальную травму»).

**Карты-знания** `[Решение GDD]`. Награда «информация» из архива превращается в карту-усиление типа `knowledge` (например, «Знание Царства Снов», «Слабое место Горного Короля»). Она даёт бонус в событиях с нужным тегом и/или раскрывает скрытые последствия (D10). Так информация становится игровой, а не просто текстом.

### Износ и поломка `[Решение владельца]`

```text
У каждого изнашиваемого усиления хранится wear (шанс поломки), старт = 1%.

После разрешения события (успех или провал), для каждого приложенного усиления:
    бросок 1..100
    если бросок <= wear:  карта УНИЧТОЖЕНА (удаляется из коллекции)
    иначе:                wear = min(100, wear + 5)

Использования:  1-е   2-е   3-е   4-е   5-е   … 10-е   … 20-е
Шанс поломки:   1%    6%    11%   16%   21%   … 46%    … 96%
```

- Бросок поломки идёт **после** броска события и броска смерти; результат показывается на экране результата отдельной строкой: «Импровизированное оружие: износ 11% → 16%» или «Импровизированное оружие раскололось».
- Износ **виден всегда** на самой карте (`⚒ 16%`) и во всплывающей подсказке в планшете: «Шанс поломки после этого события: 16%». Столп «Честный риск».
- Не изнашиваются (D18): способности Аспекта, карты-знания, Эхо.
- Если персонаж погиб, его усиления возвращаются в панель со своим износом.
- **Ремонт** (D17): событие «Легендарный кузнец» — вариант «Починить» сбрасывает износ одной выбранной карты до 1% за монеты. Цена зависит от редкости (таблица 4.12). Уничтоженную карту восстановить нельзя `[Решение владельца]`.

**Следствие для сюжета:** канонически важные Воспоминания (Серебряный Колокольчик, Саван Кукловода, Лазурный Клинок…) могут быть уничтожены. Поэтому **сюжетный вариант не может быть единственным путём, требующим изнашиваемую карту** — у сюжетного события всегда должен оставаться хотя бы один вариант без такого условия. Это проверяет валидатор (8.5).

### Выдача травмы при провале `[Решение владельца]`

```text
пул = trauma_pool варианта (если задан) или все T01–T10
пул = пул − {T07, T09} − травмы, которые уже есть у персонажа
если пул пуст: пул = все случайные травмы, которых у персонажа нет
если и он пуст: травма не выдаётся, но бросок смерти всё равно делается
травма = случайный элемент пула (равные веса)
```

Количество травм за провал — D19 (1, у `high_danger` — 2; каждая выдаётся отдельно, со своим броском смерти). Одинаковая травма на персонаже не повторяется `[Зафиксировано]`.

Примеры `trauma_pool`: бой → `physical` (T02, T03, T08, T10); холод/путь → `environment` (T01, T04); страх/ментальное воздействие → `mental` (T05, T06). Пул по умолчанию — все травмы; сужение — инструмент сценариста, чтобы травма соответствовала сцене.

### Смерть `[Решение владельца]`

```text
После выдачи каждой новой травмы:
    n = число травм на персонаже (T09 не считается — она живёт только до конца события)
    если n <= 2: шанс смерти = 0
    иначе:       шанс смерти = min(100, 15 + 20 × (n − 3))
    бросок 1..100; если бросок <= шанс смерти → персонаж погибает

Травм:        0–2    3      4      5      6      7+
Шанс смерти:  —      15%    35%    55%    75%    95% → 100%
```

- Лечение снижает число травм, а значит и шанс смерти: это главный смысл лечения.
- Шанс смерти **при следующей травме** всегда виден на карте персонажа (`☠ 15%`) и в планшете рядом со строкой «Провал».
- Смерть Санни — конец прохождения (D2). Автосохранение делается **до** броска, поэтому «Загрузить» возвращает игрока к началу хода, а не к моменту после смерти. Отдельно хранится контрольная точка начала арки.
- Смерть другого персонажа — навсегда в рамках прохождения; запись в Кодекс «Память».

### Лечение

| Способ | Что снимает | Где |
|---|---|---|
| Событие «Передышка» (инициатор `Привал` или случайное) | 1 лёгкую травму гарантированно; проверка Воли — ещё одну травму любой тяжести | любой регион |
| Награда события | конкретную травму, указанную в данных | по сценарию |
| Бессмертное Пламя Нефис | 1 физическую травму «раз за событие» (с ценой T09 Боль) | когда Нефис в коллекции |
| Переход арки | все травмы среды и T09 | конец Первого Кошмара, переход в Царство Снов |

`[Решение GDD]` После E11 (пробуждение в реальном мире) **все травмы Санни снимаются** — тело из Кошмара не переносится. Это ещё и естественный «вдох» перед Академией.

## 4.6. Источники событий: сюжет, случайные события, инициаторы

На карте события появляются тремя способами:

| Источник | Что появляется | Когда |
|---|---|---|
| Сюжет | следующее сюжетное событие | после успеха предыдущего, через 0–2 недели, без инициатора (D21) `[Решение владельца]` |
| Случайность | событие из пула случайных событий региона | каждую неделю бросок 30% (D20) |
| Инициатор | одно конкретное событие, записанное в карте | когда игрок применил инициатор |

### Инициаторы `[Решение владельца]`

| Правило | Значение |
|---|---|
| Как применить | перетащить карту-инициатор в любое место карты мира |
| Где | везде, без ограничений по региону |
| Результат | всегда одно конкретное событие из данных инициатора; случайных событий инициатор не создаёт |
| Расход | одноразовый: карта исчезает при применении и не возвращается |
| Продвигают ли сюжет | нет `[Зафиксировано]` |
| Стоит ли хода | само применение — нет; разрешение созданного события = +1 неделя `[Зафиксировано]` |

Раз инициаторы одноразовые, они становятся **ценной наградой**: «Привал» — это одно гарантированное лечение, которое игрок бережёт на крайний случай.

### Случайные события `[Решение GDD]`

- У каждого региона — пул случайных событий (`data/events/random_<регион>.json`). В пуле Первого Кошмара: «Передышка», «Обыск повозки», «Ссора рабов», «Ночной холод».
- Событие из пула не повторяется, пока пул не исчерпан; затем пул перемешивается заново (кроме помеченных `once`).
- Случайные события не продвигают сюжет и не имеют срока жизни `[Зафиксировано]`.
- Визуально — карта без римской цифры, с символом игральной кости в углу; от инициатора — с символом свечи.

### Инициаторы вертикального среза

| ID | Инициатор | Как получить | Создаёт |
|---|---|---|---|
| I01 | Первый сон | стартовый | E01 (обучение перетаскиванию) |
| I02 | Привал | E02, сюжетный вариант | SE01 «Передышка» — лечение |
| I03 | Разговор у костра | Шолар присоединился (E04, вариант 1) | SE02 — Шолар рассказывает о мире: карта-знание |
| I04 | Знак кузнеца | E17 (в Кошмаре кузнеца нет по сюжету) | SE10 «Легендарный кузнец» — сброс износа за монеты |

## 4.7. События и варианты

### Структура события

`id`, арка, регион, позиция на карте, тип (`story` / `side` / `reward`), римская цифра на рубашке, заголовок, текст сцены (2–4 предложения), арт, теги события, противник (ссылка на EnemyDef), **ровно 3 варианта** `[Зафиксировано]`, источник по главам, `canon_note`.

### Типы вариантов `[Решение GDD]`

| `check_type` | Что происходит | Как выглядит кнопка |
|---|---|---|
| `stat_check` | обычная проверка по формуле | требования + шкала шанса |
| `gate_only` | нет числовых требований; при выполнении условий — успех без броска | условия + надпись «Без броска» |
| `gate_and_check` | условия обязательны, затем бросок | условия + требования + шкала |
| `auto` | всегда успех (наградные события, E17) | «Выбрать» |
| `resource_spend` | трата маны или монет (цена в данных); при нехватке — вариант заблокирован, как жёсткое условие | цена `⛁ 4` / `◈ 3` + результат |

**Невыполненное условие ≠ низкий шанс.** Вариант с невыполненным жёстким условием выглядит заблокированным (замок, текст «Нужен: Ауро в коллекции»), кнопка неактивна. Вариант с 5% шансом — активен, шкала почти пустая.

### Последствия варианта

Для **каждого** варианта задаются **оба** исхода: `on_success` и `on_failure`, даже если исход пустой (`[]`). `[Решение GDD]` Если `on_failure` не задан явно, применяется **стандартный провал**: `add_random_trauma: 1` (D8, D19).

**Продвижение (D4):** у сюжетного события ровно один вариант помечен `story: true`; его успех закрывает событие и запускает следующее (с задержкой D21). Успех несюжетного варианта: награда применяется, вариант помечается «Выполнено» (затемнён, галочка), событие остаётся. Провал любого варианта — вариант можно повторить.

При провале событие **остаётся на поле** `[Зафиксировано]`, при повторной попытке раскрытая ранее информация (D10) остаётся раскрытой.

## 4.8. Шанс успеха — полная спецификация

### Итоговые характеристики

```text
Итог(stat) = База стадии персонажа
           + постоянные бонусы персонажа
           + Σ бонусы усилений (с учётом тегов события и владельца)
           + Σ черты персонажа (с учётом тегов события)
           + временные эффекты («в следующем событии»)
           − Σ штрафы травм (с учётом контекста)
Для расчёта шанса: Итог = max(0, Итог)
```

### Формула `[Зафиксировано]` + крайние случаи `[Решение GDD]`

```text
R = требования варианта {сила, воля, хитрость}; отсутствующее = 0
S = итоговые характеристики
Req = характеристики, где R > 0

если Req пусто:                       шанс = 100 (бросок не нужен)
если для всех stat ∈ Req: S >= R:     шанс = 100
иначе:
    база        = Σ_{Req} min(S, R)
    избыток     = Σ_{Req} max(S − R, 0)      ← только требуемые (D16)
    компенсация = избыток / 8
    шанс_точн   = min(100, (база + компенсация) / Σ_{Req} R × 100)
    шанс        = floor(шанс_точн)           ← целое, показывается и бросается

бросок: случайное целое 1..100; успех, если бросок <= шанс
шанс 0 → кнопка активна, но с подписью «Невозможно при текущем составе»
```

Одна чистая функция `ChanceCalculator.compute(stats, requirements) -> int` используется и для отображения, и для броска. Её тесты — первое, что пишется в коде (см. 8.9).

### Визуальная градация шкалы `[Решение владельца]`

Шкала окрашивается по шансу: **тёмно-красный** на очень низком, **зелёный** в середине, **золотой** на 100%. Цвет берётся из плавного градиента (Godot `Gradient`, выборка по `шанс / 100`), метка — по порогам.

| Шанс | Метка | Цвет заполнения | Опорный HEX |
|---|---|---|---|
| 0 | Невозможно | пустая шкала, багровая штриховка | `#3A0E12` |
| 1–19 | Очень низкий | тёмно-красный | `#6E1A20` |
| 20–44 | Низкий | красная медь | `#9A4A2E` |
| 45–69 | Средний | зелёный | `#4F8F55` |
| 70–89 | Высокий | светло-зелёный | `#7FAA4E` |
| 90–99 | Почти гарантированный | зелёное золото | `#B7AE45` |
| 100 | Гарантировано | **золотой**, мягкое свечение, значок `◆◆` | `#E0B43C` |

Точки градиента: `0 → #6E1A20`, `0.30 → #9A4A2E`, `0.55 → #4F8F55`, `0.85 → #8FAE4A`, `0.99 → #C2AE42`, `1.0 → #E0B43C`.

Правила читаемости:
- Процент и текстовая метка всегда написаны на шкале светлым текстом `text_main` с тёмной обводкой — цвет не единственный носитель смысла.
- Цвета шкалы темнее и насыщеннее, чем цвета модификаторов характеристик (`#6FA47B` / `#B65F63`), и живут только внутри шкалы, поэтому не путаются с ними. Требования по-прежнему отмечаются голубым `◆` / янтарным `!` `[Зафиксировано]`.
- Для игроков с нарушением цветовосприятия — настройка «Шкала шанса: цветная / монохромная» (монохромная — яркость серебра по тем же порогам).

### Анимация броска `[Решение GDD]`

На шкале шанса появляется тонкая стрелка, пробегает вправо-влево с замедлением и останавливается на выпавшем числе (0.9 с; в настройках — «быстро» 0.3 с или «без анимации»). Зона успеха (0…шанс) подсвечена. Игрок видит число и понимает исход без слов.

## 4.11. Время и временные эффекты

- Неделя +1 после разрешения любого события (сюжетного или побочного). `[Зафиксировано]`
- Временные эффекты: `this_event` (например, T09), `next_event` (сгорает после следующего разрешённого события **этого персонажа**), `N ходов`.
- Эффекты «в E09» из архива (E08: «+2 Хитрость в E09») трактуются как `next_event` + условие `event_id = E09`; если игрок сначала пройдёт побочное событие, эффект сохраняется до E09.

## 4.12. Ресурсы: мана и монеты `[Решение владельца]` + цены `[Решение GDD]`

| Параметр | Монеты ⛁ | Мана ◈ |
|---|---|---|
| Смысл | мир людей: торговля, ремесло, плата | сила Заклинания: прозрение, воля, защита души |
| Старт | **10** | **10** |
| Максимум | 999 (фактически без лимита) | **30** — мана не копится бесконечно, её выгоднее тратить |
| Видно | всегда, верхняя панель | всегда, верхняя панель |

### Доход

Оба ресурса выпадают **с равным шансом** `[Решение владельца]`:

```text
После каждого УСПЕХА события (сюжетного, случайного, от инициатора):
    бросок 50%: есть ли добыча
    если есть:  тип = монеты или мана (50 / 50)
                количество = 2–4 (сюжетное), 1–3 (случайное / от инициатора)
Провал: добычи нет.
Плюс сценарные награды в данных вариантов: adjust_resource: coins/mana, +N.
```

Ожидаемый доход ≈ 0,75 монеты и 0,75 маны за успешное событие плюс сценарные награды. За Первый Кошмар (~15 ходов) — примерно **+8–12 каждого ресурса**. Итоговые числа — Фаза 1.

Случайные события с явным уклоном: «Обыск повозки» (монеты), «Молитва у костра» (мана).

### Траты монет ⛁

| Что | Где | Цена |
|---|---|---|
| Сбросить износ усиления до 1% | «Легендарный кузнец» | обычная **3**, редкая **5**, эпическая **8**, легендарная **12** |
| Снять физическую травму / травму среды | случайное событие «Знахарь» / «Лекарь» | лёгкая **4**, тяжёлая **7**, критическая **10** |
| Купить усиление | «Торговец каравана», позже Рынок Воспоминаний | обычное **6**, редкое **10**, эпическое **16**; легендарные не продаются |
| Платный вариант события (подкуп, найм, проход) | `resource_spend` в данных события | **2–8**, задаётся сценарием |

### Траты маны ◈

| Что | Где | Цена | Ограничение |
|---|---|---|---|
| **Прозрение** — раскрыть скрытые последствия одного варианта (D10) | значок `?` в планшете | **1** | — |
| **Концентрация** — +1 к одной характеристике до конца события | кнопка `+◈` рядом с характеристикой в планшете | **3** | не более 2 раз за событие |
| **Оберег** — если в этом событии будет бросок смерти, его шанс делится пополам (вниз) | переключатель в планшете до выбора варианта | **4** | списывается, **только если бросок смерти действительно случился** |
| **Медитация** — снять ментальную травму (T05, T06, T07) | событие «Передышка» | **5** | — |
| Ритуальный вариант события | `resource_spend` в данных | **2–8** | задаётся сценарием |

Прозрение списывается сразу (знание нельзя «забыть»). Концентрация — черновик: пока игрок перекладывает карты, шансы уже пересчитаны, но мана списывается только при нажатии варианта.

Архитектура: `RunState.resources = {"coins": 10, "mana": 10}`; траты — через `adjust_resource` в той же транзакции, что и остальные эффекты.

## 4.13. Карта мира, регионы и арки

- Карта мира — плоский 2D-арт региона. События — вертикальные карты Таро, стоящие в точках интереса. `[Зафиксировано]`
- Сюжетное событие отличается от побочного: **сюжетное** — золотистая римская цифра и лёгкое свечение; **побочное** — без цифры, значок инициатора в углу.
- Каждая арка = регион с собственным фоном, музыкой и цветовым акцентом (см. 6.3).
- Переход арки — полноэкранная заставка с названием, итогами (недель, травм, найденных карт) и цитатой-пересказом.

## 5.3. Кривая сложности среза

С Санни-Рабом (3 / 5 / 6) и без усилений:

| Событие | Лучший чистый шанс | Роль в кривой |
|---|---:|---|
| E01–E02 | 100% | обучение, провал почти невозможен |
| E03 | 100% (без награды) / 85% (с наградой) | первый выбор «риск ради карты» |
| E04 | 100% (бежать одному) | первое моральное решение |
| E05 | 78–85% | первая настоящая угроза, нужен Ауро или U01 |
| E06–E08 | 85–100% | передышка, подготовка к E09 |
| E09 | ~73% (+ бонусы E08) | кульминация, провал = 2 травмы, реальный риск смерти |
| E10 | 50–60% (+ бонусы вариантов 2–3 и Концентрация) | финальное испытание, повторы ожидаемы |
| E11 | 100% | награда и эволюция карты |

Цель Фазы 1 — убедиться, что средний игрок проходит срез за 14–20 недель (ходов), получает 2–4 травмы и **хотя бы раз оказывается в зоне риска смерти** (3 травмы), но погибает Санни не чаще чем в 1 из 5 прохождений. Если чаще — повышаем доступность «Передышки» в пуле, а не меняем формулу владельца.

Износ в срезе: Импровизированное оружие (U01), полученное в E03 и используемое во всех боях, к E09 будет иметь износ ~16–21%. Потеря его перед кульминацией — ожидаемая и интересная ситуация.

| Получен «Привал» | инициатор | «Инициатор создаёт одно событие и исчезает. Берегите его» |
| Первое усиление | веер на персонаже | «До трёх усилений. Цифры изменятся сразу» |

Подсказки выключаются в настройках и не повторяются.

# 6. Визуальный дизайн

**Визуальное решение от 24.09.2026:** [[11 — Визуальная спецификация интерфейса]] и [[SunLess — Коллаж интерфейса]] фиксируют окончательный вид, компоновку и размеры при 1920 × 1080. Для визуальной геометрии и размеров карт файл 11 имеет приоритет над ранними схемами 6.6–6.9: слева добавлена навигация, карта мира и карточки получают точные размеры, нижняя часть планшета события делится около 50/50. Игровые правила, формулы и реальные тексты событий по-прежнему определяются GDD и файлами событий.

## 6.1. Художественное направление

**«Тушь, тень и лунное серебро».** Мир — тёмный, холодный, почти монохромный; карты — единственные «драгоценные» объекты на экране. Эстетика карт Таро и старинных гравюр, но без стимпанка и без глянцевой фэнтези.

| Принцип | Как выражается |
|---|---|
| Тень — главный материал | фоны регионов — тёмная тушь с размытыми краями, туман, силуэты; свет только там, где есть интерактив |
| Карты — артефакты | фактура плотной бумаги, тиснение рамки, лёгкий износ; при наведении — блик |
| Серебро вместо золота | главный акцент интерфейса — холодное серебро (Санни, тени, луна); золото — только редкость и сюжетные события |
| Минимум HUD | всё, что не нужно для текущего решения, приглушено |
| Системные сообщения Заклинания | отдельный стиль: светящийся текст в квадратных скобках, плывущий поверх экрана (как «голос Заклинания» в книге) |

Арт в вертикальном срезе: **заглушки → полуфинальные иллюстрации** только для E01–E11 и 4 персонажей. Стиль иллюстраций: живописный 2D, приглушённая палитра, силуэты читаются в миниатюре 140 px.


`[Решение GDD]` Нижняя часть делится **30 / 70**, а не 50 / 50: варианты с русскими названиями, требованиями и последствиями занимают больше места, чем кармашек. Проверить на прототипе.

Правила отображения:
- Каждая цифра требования: значок характеристики + число + `◆` (голубой) или `!` (янтарный). Цвет всегда продублирован знаком. `[Зафиксировано]`
- Итоговая характеристика: `база→итог`, итог окрашен `stat_up` / `stat_down` / `stat_neutral`. При наведении — разбивка: «База 3, U01 +2».
- Сюжетный вариант отмечен значком `📖` и подписью «Продвигает историю». Выполненный несюжетный вариант — затемнён, галочка «Выполнено».
- Заблокированный вариант: затемнён, замок, строка «Нужен: Ауро в коллекции» или «Нужно: ⛁ 4», шкалы нет.
- Мана в планшете: кнопки `+◈` у каждой характеристики (Концентрация, 3 маны), значок `?◈` у скрытых последствий (Прозрение, 1 мана), переключатель «Оберег ◈4» под травмами персонажа — активен, когда у персонажа 2+ травм.
- Нажатие на вариант **сразу** запускает бросок `[Зафиксировано]`. Чтобы избежать случайных кликов: кнопка активна только когда в кармашке есть персонаж; нажатие срабатывает на отпускании кнопки мыши; подсветка при наведении — явная.
- Клик по другой карте-событию на карте мира (видна по краям планшета) заменяет содержимое планшета `[Зафиксировано]`; черновик прежнего события сохраняется.

## 6.12. Доступность

- Цвет никогда не единственный носитель смысла: знаки `◆` / `!`, стрелки `→`, текстовые метки шанса. `[Зафиксировано]`

## 8.5. Валидатор контента

Запускается при старте (debug) и отдельной кнопкой в редакторе (`@tool`-скрипт). Ошибки:

- дубликат ID; ссылка на несуществующую карту / событие / тег / травму / регион;
- у события не 3 варианта;
- у варианта нет `on_success` или `on_failure`;
- `stat_check` с нулевой суммой требований (должен быть `gate_only`);
- у сюжетного события не ровно один `story_option` (кроме `reward`); цепочка `next_story_event` обрывается или зацикливается;
- сюжетный вариант требует изнашиваемую карту или конкретного смертного персонажа (после поломки/смерти сюжет станет непроходимым);
- способность без владельца или способность в списке усилений; `add_ability` для персонажа, которому она не принадлежит;
- у сюжетного события нет ни одного варианта без условия на изнашиваемую карту или конкретного смертного персонажа (риск тупика после поломки/смерти);
- `trauma_pool` содержит неизвестную категорию; инициатор без ссылки на конкретное событие;
- `add_trauma` с HP-подобной формулировкой (проверка по словарю);
- событие требует персонажа, который недоступен в этой арке;
- ключ текста отсутствует в локализации.

Отчёт «тупиков»: симулятор перебирает все исходы E01–E11 (успех/провал каждого варианта) и проверяет, что из любого состояния достижим E11.

## 8.6. Сохранения

| Параметр | Значение |
|---|---|
| Путь | `user://saves/slot_1.json` … `slot_3.json`, `autosave.json` |
| Когда | автосохранение после каждого разрешённого события и при выходе; ручное — в меню паузы |
| Формат | JSON, `save_version`, `content_version`, дата, неделя, регион |
| Содержимое | только ID и состояние: коллекция, `CharacterState` (стадия, травмы, постоянные бонусы, временные эффекты, статус: жив/погиб), износ каждого усиления, флаги, пул и история случайных событий, открытые/завершённые события, раскрытые последствия, черновики, ресурсы, ожидающее сюжетное событие и оставшаяся задержка, состояние RNG, журнал |
| Запись | сначала `*.tmp`, затем переименование (защита от порчи при сбое) |
| Загрузка | проверка версии → миграция → проверка всех ID через `ContentDB` → при ошибке понятное сообщение, файл не трогаем |
| Сейв-скам | RNG-состояние хранится в сохранении, поэтому перезагрузка перед тем же выбором даёт тот же бросок |

| 2.5 Экран | карта мира с маркерами, нижняя панель, `CardView` (заглушки) | события видны, карты листаются |
| 2.6 Планшет | кармашек, drag & drop, веер, 3 варианта, шкалы, пересчёт в реальном времени | смена усиления мгновенно меняет шансы |
| 2.7 Разрешение | бросок, экран результата, неделя, открытие следующего события | можно пройти E01–E05 |
| 2.8 Сохранения | автосейв, слоты, загрузка, проверка версий | сохранить → выйти → загрузить = то же состояние |
| 2.10 Ресурсы | мана и монеты в верхней панели, добыча, Концентрация / Прозрение / Оберег, `resource_spend`, задержка сюжетного события | старт 10 / 10; трата отражается в шансах до нажатия |
| 2.9 Инициаторы и случайные события | перетаскивание на карту, исчезновение инициатора, пул случайных событий, износ, бросок смерти | «Привал» лечит травму |

**Результат:** сборка `0.2.x` на заглушках.
**Готово, когда:** новая игра → событие → провал → травма → лечение → повтор → успех → сохранение → загрузка работают; `gate_only` и нулевые требования не ломают формулу.
