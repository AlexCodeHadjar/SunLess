# Скиллы, плагины и экономия лимитов — руководство

Для владельца SunLess. Написано 07.10.2026. Относится к Claude Code (окно «Code» в приложении Claude).

## 1. Что это такое

| Понятие | Простыми словами | Пример |
|---|---|---|
| **Скилл** | Папка с инструкцией («как делать X»). Claude видит только короткое описание (30–100 токенов) и читает всю инструкцию, когда задача подходит | `simplify`, `docx`, `cli-anything-sunless-map` |
| **Команда** (`/имя`) | Скилл, который вы вызываете сами, набрав `/` | `/simplify`, `/code-review` |
| **Плагин** | Набор скиллов, команд и агентов, который ставят одним действием | Superpowers, Frontend Design |
| **MCP-сервер** | Подключение к внешней программе или сервису (браузер, Godot, почта) — даёт Claude новые инструменты | `claude-in-chrome`, `Claude_Browser` |
| **Хук** | Правило «всегда делай X при событии Y» в `settings.json`; выполняет его сама программа, а не Claude | «после каждой правки запускай тесты» |
| **`CLAUDE.md`** | Файл правил проекта; читается в каждой сессии целиком | карта проекта SunLess |
| **Память** | Файлы в `.claude/projects/…/memory`; Claude читает индекс в начале сессии | ваши решения и предпочтения |

## 2. Как скиллы запускаются

Есть три способа.

1. **Вы пишете `/имя`** — например `/simplify` или `/code-review high`. Это самый надёжный способ: скилл точно запустится.
2. **Вы просите словами**: «используй скилл simplify на изменениях этой сессии». Claude вызывает его сам.
3. **Автоматически**: если задача подходит под описание скилла, Claude может запустить его без просьбы. Но это не гарантировано — Claude сам решает, подходит ли описание.

Чтобы увидеть, какие скиллы есть: наберите `/` и появится список. В моём окне сейчас доступны, например: `simplify`, `code-review`, `security-review`, `loop`, `schedule`, `init`, `update-config`, `docx`, `pdf`, `xlsx`, `cli-anything-sunless-map` (карты SunLess).

## 3. Как включить, выключить, поставить

Делается в **обычном окне Claude Code** командой `/plugin` (в этом приложении она может быть недоступна; тогда — из терминала).

| Что хотите | Команда |
|---|---|
| Посмотреть, что установлено, и включить или выключить | `/plugin` (вкладки «Installed», «Discover») |
| Добавить каталог плагинов | `/plugin marketplace add anthropics/claude-plugins-official` |
| Поставить плагин | `/plugin install имя@каталог` |
| Выключить, не удаляя | `/plugin disable имя@каталог` |
| Включить обратно | `/plugin enable имя@каталог` |
| Удалить | `/plugin uninstall имя@каталог` |

После установки или выключения начните **новую сессию** (или `/reload-plugins`), чтобы изменения подхватились.

Свой скилл: попросите «создай скилл, который…» (поможет скилл `skill-creator`) или положите папку со `SKILL.md` в `.claude/skills/<имя>/` проекта — тогда он действует только в проекте и лежит вместе с ним в git. Именно так сделан скилл карт `cli-anything-sunless-map`.

## 4. Как сделать, чтобы скилл работал «по умолчанию»

Скилл не включается «всегда» одной галочкой — есть четыре рабочих способа, от слабого к сильному:

1. **Хорошее описание.** В `SKILL.md` первое поле `description` — это то, по чему Claude решает, запускать ли скилл. Чем точнее («Используй, когда просят проверить карту главы SunLess»), тем чаще он запускается сам.
2. **Строка в `CLAUDE.md`.** Например: «После крупной фазы запускать `/simplify`», «Перед коммитом — `/code-review`». Claude читает это каждую сессию и следует.
3. **Память.** Скажите «запомни: после каждой фазы запускай simplify» — я запишу это в память, и это сработает в будущих сессиях.
4. **Хук** (самое жёсткое). «Каждый раз, когда … — делай …» нельзя гарантировать ни памятью, ни `CLAUDE.md`: Claude может забыть. Это делается в `settings.json` через хук, и его исполняет программа. Попросите: «настрой хук: после каждой правки файла `.gd` запускать компиляцию» — сработает скилл `update-config`.

## 5. Как просить, чтобы не тратить лимит

- **Называйте скилл прямо**: «запусти /simplify на core/combat/skirmish» — дешевле, чем «посмотри, нет ли проблем».
- **Одна цель — одно сообщение.** «Продолжай» без уточнения заставляет искать работу.
- **Скилл читается целиком при запуске** и остаётся в контексте до конца сессии. Запускайте нужное, а не «на всякий случай».

## 6. Какие скиллы что стоят и нужны ли вам

| Скилл / плагин | Для чего | Вам |
|---|---|---|
| `simplify` (встроен) | Ищет повторы и лишнюю работу в изменённом коде и сразу чинит. Баги не ищет | **Да**, после каждой крупной фазы |
| `code-review` (встроен) | Ищет настоящие ошибки в изменениях. `/code-review high` — шире; `--fix` — сразу применить | **Да**, перед коммитом больших фаз |
| `security-review` | Проверка безопасности изменений | Редко (игра без сети) |
| `docx`, `pdf`, `xlsx` | Word, PDF, таблицы | Не нужны: Word уже собирает `tools/docx_lib.py` |
| `cli-anything-sunless-map` | Редактор карт глав | **Да**, для любых карт |
| `init` | Создаёт `CLAUDE.md` | Уже сделан |
| `update-config`, `fewer-permission-prompts` | Настройка разрешений и хуков, меньше вопросов «можно ли?» | **Да**, один раз |
| `loop`, `schedule` | Повтор по расписанию | Не нужны |
| Superpowers | Идея → спецификация → план → код → проверка; тесты вперёд; проверка перед «готово» | **Осторожно**: см. раздел 7 |
| Frontend Design | Красивый веб-дизайн | Нет: у вас Godot, не сайт |
| Code Simplifier | То же, что встроенный `simplify` | Не нужен |

## 7. Superpowers и Frontend Design: что делают и во что обходятся

В списке скиллов моего окна сегодня уже появились скиллы `superpowers:*` и `frontend-design` — видимо, плагины установлены.

**Superpowers** — набор из ~14 скиллов. Главный из них, `using-superpowers`, требует вызывать скилл **перед любым ответом**, даже перед уточняющим вопросом. Следствия для вас:

- Плюс: порядок («сначала план, потом код»), проверка перед словами «готово», разбор ошибок по шагам.
- Минус: больше шагов и больше текста в каждой задаче, значит быстрее уходит лимит. У вас уже есть такой порядок: ТЗ → решения вопросами → фазы → тесты.
- Мой совет: **держите его выключенным** и включайте на одну сложную задачу, где хочется строгости (например, баг, который никак не ищется — тогда `superpowers:systematic-debugging`).

**Frontend Design** — для сайтов и веб-страниц. Для Godot бесполезен; **выключите**, чтобы он не занимал место в списке.

Как выключить: `/plugin` → выберите плагин → «Disable»; затем новая сессия.

## 8. Как тратить меньше лимита (главное)

1. **Новая сессия на каждую фазу.** Это самое важное. Контекст в длинной сессии пересылается заново при каждом шаге; у нас он дошёл до ~75% окна. Закончили «Схватку Ф5» — новый чат с короткой вводной (шаблон ниже).
2. **Команды `/clear` и `/compact`.** `/clear` — чистый лист при смене задачи; `/compact` — сжать длинный разговор, сохранив суть.
3. **Короткий `CLAUDE.md`.** Он грузится целиком каждый раз. Редко нужное лучше выносить в скиллы (читаются только когда нужны).
4. **Отключайте ненужные плагины и MCP-серверы.** Каждый занимает место в контексте (у меня только описание инструментов — около 17 тыс. токенов).
5. **Не просите лишнего вывода.** Логи тестов и большие файлы остаются в контексте. Хорошая просьба: «запусти тесты и скажи только число провалов».
6. **Картинки — по одной и только когда нужна проверка глазами.**
7. **Полный прогон тестов — один раз перед коммитом.** Во время работы — только нужный набор.
8. **Английскую версию ТЗ делать в конце фазы, не при каждой правке.**
9. **Следите за лимитом.** Команда `/usage` показывает расход 5-часового и недельного лимитов; скилл `explain-usage` объясняет, куда ушли токены этой сессии.
